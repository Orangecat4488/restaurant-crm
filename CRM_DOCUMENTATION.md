# 🍽️ Restaurant CRM — Полная документация системы

Комплексная CRM / POS-система для автоматизации ресторанов, кафе и заведений общественного питания. Построена на стеке **React + TypeScript (Frontend)** и **Express + TypeScript + SQLite (Backend)** с полноценной ролевой моделью (RBAC) и JWT-авторизацией.

## 1. Архитектура и стек технологий

### Frontend:
- **React 18 + TypeScript** — строго типизированный компонентный UI.
- **Vite** — быстрая сборка и HMR-сервер разработки со встроенным API-проксированием.
- **Zustand** — реактивное управление глобальным состоянием с персистентностью в `localStorage`.
- **React Router v6** — декларативная маршрутизация с ролевыми гардами (`ProtectedRoute`, `AdminRoute`, `PublicRoute`).
- **Lucide Icons** — векторные иконки интерфейса.
- **Recharts** — графики и визуализация финансовых показателей.

### Backend:
- **Node.js + Express (ESM NodeNext)** — модульный REST API сервер.
- **SQLite (node:sqlite DatabaseSync)** — встроенная база данных с нулевыми нативными зависимостями, поддержкой `WAL` и внешних ключей.
- **JWT (JSON Web Tokens)**:
  - **Access Token**: короткоживущий (15 минут), передается в заголовке `Authorization: Bearer <token>`.
  - **Refresh Token**: долгоживущий (7 дней), передается в `HttpOnly`, `SameSite` cookie с уникальным `jti` UUID и обязательной валидацией/ротацией в таблице `refresh_tokens`.
- **Bcrypt.js** — криптографическое хэширование паролей (12 раундов).
- **Безопасность**: Helmet (CSP, HSTS, NoSniff), Express-Rate-Limit, Zod-валидация, XSS-санитизация, CSRF-защита.

## 2. Ролевая модель доступа (RBAC)

Система поддерживает 3 основные роли с иерархическим разграничением прав как на стороне сервера (middleware `requireRole`), так и в интерфейсе:

| Роль | Описание | Доступные модули и права |
| :--- | :--- | :--- |
| **Администратор (`admin`)** | Владелец / управляющий | • Полный доступ ко всем модулям системы.<br>• Управление персоналом (`/users`): создание, сброс паролей, смена ролей, блокировка, удаление.<br>• Удаление любых блюд, категорий и заказов.<br>• Просмотр финансовой аналитики, кассовых смен и отчетов. |
| **Менеджер зала (`manager`)** | Администратор смены | • Управление каталогом блюд и категориями (создание, редактирование цен, фото, статусов).<br>• Управление заказами (изменение статусов, состава).<br>• Кассовые смены: открытие/закрытие смены, снятие X/Z-отчётов, внесения и инкассация.<br>• Просмотр отчётов и аналитики выручки.<br>• Просмотр списка сотрудников (без возможности создания/удаления администраторов). |
| **Сотрудник (`employee`)** | Официант / кассир | • Создание и ведение заказов через POS-терминал кассира (`/cashier`).<br>• Просмотр меню и списка категорий.<br>• Печать чеков и выбор способа оплаты.<br>• Заблокирован доступ к управлению сотрудниками и удалению данных. |

## 3. Модули и функциональность системы

### 3.1. Авторизация и безопасность
- **Форма входа**: авторизация по Email и Паролю.
- **Защита от брутфорса**: Rate limiter ограничивает число попыток входа; аккаунт автоматически временно блокируется на 15 минут после 5 неверных попыток ввода пароля.
- **Двухфакторная схема токенов**:
  - `Access Token` хранится в памяти приложения и автоматически обновляется в фоновом режиме через `/api/auth/refresh`.
  - `Refresh Token` хранится в безопасном `HttpOnly` Cookie, недоступном для JavaScript (защита от кражи через XSS).
- **Настоящий Logout**: при выходе токен инвалидируется на сервере в SQLite (помечается `revoked = 1`), что исключает возможность его повторного использования даже при перехвате.
- **Смена пароля**: смена пароля в профиле автоматически отзывает все ранее выданные refresh-токены на всех устройствах.

---

### 3.2. Главная панель (Dashboard)
- **Сводка за день**:
  - Текущая выручка ресторана.
  - Количество оформленных и оплаченных заказов.
  - Средний чек за день.
  - Загрузка столов / кассы.
- **Интерактивные графики**:
  - Динамика продаж по часам дня.
  - График выручки по дням недели.
- **Быстрый просмотр**:
  - Топ самых популярных блюд.
  - Список последних активных заказов со статусами выполнения.

---

### 3.3. POS-Терминал кассира (Cashier)
- **Каталог товаров**:
  - Удобная плиточная сетка блюд с изображениями, ценами и категориями.
  - Быстрый поиск по названию блюда и переключение между категориями (Салаты, Супы, Горячее, Напитки, Десерты).
- **Интерактивный чек (Корзина)**:
  - Добавление позиций в 1 клик.
  - Изменение количества, удаление отдельных позиций или полная очистка чека.
  - Добавление примечаний и модификаторов к блюдам (например: «без лука», «двойной сыр»).
- **Оплата и фискализация**:
  - Выбор типа оплаты: **Наличные**, **Банковская карта**, **Онлайн-оплата**.
  - Калькулятор сдачи при оплате наличными.
  - Автоматическая генерация фискального чека и печать.

---

### 3.4. Управление заказами (Orders)
- **Журнал всех заказов**:
  - Таблица заказов с номерами, именем гостя, телефоном, составом, суммой и датой.
  - Поиск заказов по номеру чека или контактным данным.
- **Жизненный цикл заказа**:
  - `pending` (Новый заказ, ожидает подтверждения).
  - `preparing` (Готовится на кухне).
  - `ready` (Готов к выдаче / подаче гостю).
  - `completed` (Выполнен и закрыт).
  - `cancelled` (Отменен).
- Мгновенное обновление статусов менеджером или официантом.

---

### 3.5. Меню и товары (Products)
- Каталог блюд с ценами, описаниями, категориями и статусом активности.
- Создание новых позиций меню с привязкой к категориям.
- Редактирование цен, описаний и изображений блюд.
- Возможность временного скрытия блюда из меню (деактивация) без удаления истории заказов.
- Удаление блюд доступно только Администратору.

---

### 3.6. Категории меню (Categories)
- Создание и настройка категорий блюд.
- Назначение персонального цветового маркера для каждой категории для быстрого визуального поиска в терминале.
- Защита целостности данных: система блокирует удаление категорий, к которым привязаны активные блюда.

---

### 3.7. Чеки и транзакции (Receipts)
- История всех выбитых фискальных чеков.
- Фильтрация по типам оплат и периодам.
- Просмотр детальной информации по чеку: список блюд, примененные скидки, кассир, дата и время.
- Функция повторной печати чека (`Print Receipt`).

---

### 3.8. Кассовая книга и смены (Balance)
- **Управление сменами**:
  - Открытие смены с фиксацией начального остатка наличных в кассе.
  - Закрытие смены с генерацией **Z-отчёта**, фиксацией фактической суммы и автоматическим расчетом излишков или недостачи.
  - Печать промежуточного **X-отчёта** без закрытия смены.
- **Кассовые операции**:
  - **Внесение (Deposit)**: внесение разменной монеты с указанием суммы и примечания.
  - **Инкассация (Withdrawal)**: изъятие выручки с проверкой остатка и обязательным обоснованием.
- **История кассовых смен**:
  - Архив закрытых смен с детализацией по выручке, наличным и безналичным продажам.

---

### 3.9. Аналитика и отчёты (Reports)
- Финансовая отчетность за день, неделю, месяц.
- Структура выручки по категориям меню и типам оплат.
- Анализ средней суммы чека и пиковых часов нагрузки.
- Экспорт и печать сводных отчетов для бухгалтерии.

---

### 3.10. Управление персоналом (Users) — `Admin Only`
- Список всех зарегистрированных пользователей системы с указанием Email, роли, даты создания и активности.
- Создание новых сотрудников с валидацией пароля (минимум 8 знаков, заглавные/строчные буквы, цифры, спецсимволы).
- Редактирование профилей (имя, email, смена роли).
- Мгновенная блокировка доступа уволенным сотрудникам (`toggle-active`).
- Защита от удаления собственного аккаунта и самоблокировки администратора.

## 4. API Endpoints (Спецификация)

### Аутентификация (`/api/auth`)
- `POST /api/auth/login` — вход в систему (возвращает `accessToken` и `user`, устанавливает `refreshToken` cookie).
- `POST /api/auth/refresh` — обновление `accessToken` по cookie `refreshToken` (ротация токена).
- `POST /api/auth/logout` — отзыв refresh-токена в базе данных и очистка cookie.
- `GET /api/auth/me` — получение данных текущего авторизованного пользователя.
- `POST /api/auth/change-password` — смена пароля с отзывом всех активных сессий.
- `POST /api/auth/verify-token` — валидация токена.

### Пользователи (`/api/users`) — `admin`, `manager`
- `GET /api/users` — список пользователей с пагинацией и поиском (`admin`, `manager`).
- `GET /api/users/:id` — просмотр пользователя по ID (`admin`, `manager`).
- `POST /api/users` — создание нового пользователя (**`admin` only**).
- `PATCH /api/users/:id` — обновление пользователя (`admin`, `manager`).
- `DELETE /api/users/:id` — удаление пользователя (**`admin` only**).
- `POST /api/users/:id/toggle-active` — блокировка/разблокировка (`admin`, `manager`).

### Товары и меню (`/api/products`)
- `GET /api/products` — список блюд (`admin`, `manager`, `employee`).
- `GET /api/products/:id` — карточка блюда (`admin`, `manager`, `employee`).
- `POST /api/products` — создание блюда (`admin`, `manager`).
- `PATCH /api/products/:id` — редактирование блюда (`admin`, `manager`).
- `DELETE /api/products/:id` — удаление блюда (**`admin` only**).

### Категории (`/api/categories`)
- `GET /api/categories` — список категорий (`admin`, `manager`, `employee`).
- `GET /api/categories/:id` — просмотр категории (`admin`, `manager`, `employee`).
- `POST /api/categories` — создание категории (`admin`, `manager`).
- `PATCH /api/categories/:id` — редактирование категории (`admin`, `manager`).
- `DELETE /api/categories/:id` — удаление категории (**`admin` only**).

### Заказы (`/api/orders`)
- `GET /api/orders` — список заказов (`admin`, `manager`, `employee`).
- `GET /api/orders/:id` — карточка заказа (`admin`, `manager`, `employee`).
- `POST /api/orders` — создание заказа (`admin`, `manager`, `employee`).
- `PATCH /api/orders/:id` — обновление статуса или данных заказа (`admin`, `manager`).
- `DELETE /api/orders/:id` — удаление заказа (**`admin` only**).

## 5. Безопасность и отказоустойчивость

1. **Хранение секретов**: Ключи шифрования JWT (`JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`) хранятся исключительно в `.env`.
2. **Пароли**: Хэшируются через `bcryptjs` (12 раундов) и никогда не возвращаются в ответах API.
3. **Защита от XSS**: Входные данные санитизируются middleware `sanitizeInput`, исключая пароли и токены.
4. **Защита от SQL-инъекций**: 100% запросов к SQLite выполняются через параметризованные стейтменты (`prepare(?).run(...)`).
5. **CORS и Заголовки**: Доступ к API строго ограничен через `FRONTEND_URL`, настроены заголовки `Helmet` (`X-Frame-Options`, `nosniff`, `HSTS`, `CSP`).

## 6. Инструкция по запуску и разработке

### Предварительные требования:
- Node.js >= 20.x

### 1. Установка зависимостей:
```bash
# В корне проекта (Frontend)
npm install

# В директории сервера (Backend)
cd server && npm install && cd ..
```

### 2. Запуск в режиме разработки:
```bash
# Запуск Backend сервера (порт 3001)
cd server && npm run dev

# Запуск Frontend клиента (порт 5173, в отдельном терминале)
npm run dev
```

### 3. Сборка для продакшена:
```bash
# Сборка Backend
cd server && npm run build && cd ..

# Сборка Frontend
npm run build
```
